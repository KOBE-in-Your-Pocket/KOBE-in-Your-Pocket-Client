# Android（Google Play）リリース手順

iOS 版（`apple/README.md`）と同じ `develop` のコードを Google Play に出すための手順。
**個人アカウントで進める前提**（理由は §1）。リードタイムの長いものから書いてあるので、
順番どおりに進めること。

## 前提: v1 で出す機能の範囲

`src/shared/config/feature-flags.ts` の `IS_USER_CONTENT_ENABLED` が `false` のため、
**v1 はサインイン・レビュー投稿・アカウント作成を提供しない**（#306）。これが Play 側の
作業量を大きく変える。

| 項目                          | v1 での扱い                                                                                                                    |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Google サインイン             | **使わない**。OAuth クライアント ID と、そのための SHA-1 登録は不要                                                            |
| アカウント削除用の Web ページ | **不要**。Play はアカウント作成を提供するアプリに「アプリ外（Web）からの削除要求窓口」を求めるが、作成機能が無いため該当しない |
| Google マップ                 | **使う**。API キーと SHA-1 の登録が必要（§2）                                                                                  |
| 位置情報                      | 使う。端末内で完結し、経路案内で外部地図アプリへ渡すときだけ外へ出る                                                           |
| 要求する権限                  | `ACCESS_COARSE_LOCATION` / `ACCESS_FINE_LOCATION` のみ                                                                         |

サインインを解禁するとき（#556）は、OAuth クライアントの SHA-1 登録とアカウント削除の
Web 窓口が追加で必要になる。**本手順書は v1 の範囲しか書いていない。**

## §1 Play デベロッパーアカウント（個人で進める）

**個人アカウントで進める方針に決定。** 組織アカウントなら 12 人 × 14 日のクローズドテスト要件が
免除されるが、組織登録には **D-U-N-S 番号**が必要で、D-U-N-S は事業者・組織に発行されるもの。
このチームに法人格は無く、Apple Developer も個人アカウントのため流用できる D-U-N-S も無い。
大学名義で公開する選択肢もあるが、大学が法的責任を負うため学生側だけでは決められない。

> [!IMPORTANT]
> **14 日は実時間なので、他の作業より先に始めること。**
> アカウントを作ってクローズドテストを開始してしまえば、その 14 日の間に残りの開発
> （クライアント側の修正や審査準備）を進められる。後回しにすると、コードが全部できてから
> 14 日待つことになる。
>
> もう 1 つ、**最初の AAB をアップロードしないと Play アプリ署名鍵の SHA-1 が取れない**
> （§2 の 3 番目）。早くアップロードするほど早く詰まりが取れる。

### 要件

個人アカウント（2023/11/13 以降に作成）が製品版を公開するには、

- **クローズドテスト**で
- **12 人以上**のテスターが
- **14 日間連続で opt-in したまま**

である必要がある。**内部テスト（internal）はカウントされない。** Google の表現は
"run a **closed** test"。

> 2024 年 12 月に 20 人 → 12 人へ緩和されている。古い情報（20 人）を見て判断しないこと。

### 証明のしかた

**書類やスクリーンショットは出さない。Google が Play Console 側で自動的に数える。**
ダッシュボードに opt-in 人数と継続日数の進捗が出て、条件を満たすと「製品版アクセスを申請」が
押せるようになる。

ただし申請フォームには、**どうテスターを集めたか・どんなフィードバックを得たか・それを受けて
何を変えたか**を文章で書く欄がある（人が読む）。「14 日放置して申請を押すだけ」ではないので、
テスト中に出た指摘と対応をメモしておくこと。

### 進める順番

```
Play 個人アカウント作成
  └ AAB をクローズドテスト（alpha）にアップロード
      ├ Play アプリ署名鍵の SHA-1 が取れる → GCP に登録（§2 の 3 番目）
      └ テスター 12 人以上を opt-in させる
          └ 14 日連続で維持（この間に残りの開発を進める）
              └ 製品版アクセスを申請
```

### テスターの集め方と手順

**開発者側**

1. Play Console → テストとリリース → テスト → **クローズドテスト** → トラックを管理
2. テスターを追加する。2 通りある
   - **Google グループ**（推奨）… `グループ名@googlegroups.com` を指定する。
     人の入れ替えがグループ側で済むので楽
   - **メールリスト**… カンマ区切り または CSV。1 リスト 2,000 人・1 トラック 50 リストまで。
     **CSV のアップロードは既存のアドレスを上書きする**ので注意
3. AAB をアップロードしてリリースを作成する
4. **アプリの状態が「公開済み」になると opt-in リンクが表示される**（それまで出ない。
   「リンクが見つからない」はこれが原因のことが多い）
5. opt-in リンクをテスターに配る

**テスター側**

1. 配られた opt-in リンクを開く
2. テスターの責任についての説明が出る → **「テスターになる」を押す**
3. 同じページの Play ストアへのリンクからインストールする
4. **14 日間 opt-out しない**

**詰まりやすい点**

- **opt-in に登録するアドレスは、その人が Play ストアで使っている Google アカウントのもの。**
  別アドレスを登録すると、リンクを開いても「このアプリは利用できません」になる。
  いちばん多い詰まり
- 各自**別の Google アカウント**が必要
- **12 人ぴったりは危険。** 1 人 opt-out すると条件を割る。15 人程度集める
- 入れて放置ではなく実際に起動して使ってもらう。申請フォームにフィードバックを書く必要がある

## §2 Google Cloud 側（マップの API キー）

マップの API キーを「Android アプリ」で制限している場合、**呼び出し元の署名証明書の SHA-1 を
すべて登録する**必要がある。登録するのは 3 つ。

| #   | 鍵                    | 使う場面                                        | 取り方                                        |
| --- | --------------------- | ----------------------------------------------- | --------------------------------------------- |
| 1   | デバッグキーストア    | ローカルの開発ビルド                            | 下記コマンド                                  |
| 2   | EAS のアップロード鍵  | `eas build` で作った APK / AAB を直接入れたとき | `eas credentials -p android`                  |
| 3   | **Play アプリ署名鍵** | **Play から配信されたアプリ**                   | Play Console → リリース → 設定 → アプリの署名 |

```bash
# 1. デバッグキーストア
keytool -list -v -keystore ~/.android/debug.keystore \
  -alias androiddebugkey -storepass android -keypass android

# 2. EAS のアップロード鍵（対話形式。Keystore の情報に SHA-1 が出る）
eas credentials -p android
```

> [!WARNING]
> **3 番目（Play アプリ署名鍵）を忘れると、切り分けづらい不具合になる。**
> Play はアップロードした AAB を自分の鍵で**再署名**して配信するため、EAS から直接入れた
> ビルドでは動くのに、**Play 経由で入れたものだけマップが表示されない**という形で出る。
> 3 番目の SHA-1 は最初の AAB をアップロードした後でなければ Play Console に出てこないので、
> 「アップロード → SHA-1 を登録 → 配信して確認」の順になる。

API キー自体は 1 つで、3 つの SHA-1 を同じキーの「アプリの制限」に並べて登録する。

## §3 EAS の環境変数

`eas.json` の `build.production.env` には `EXPO_PUBLIC_API_BASE_URL` しか書いていない。
**マップの API キーは EAS の環境変数に入れる**（リポジトリに置かない）。

ローカルの `.env` はダミー値が入っていることがあるので、ローカルでマップが出ないことと
本番ビルドは別問題として切り分けること。

```bash
# 現在の登録内容を確認
eas env:list --environment production

# 登録（値を履歴に残したくないので、引数なしで対話形式にするのも可）
eas env:create --environment production \
  --name GOOGLE_MAPS_API_KEY --value "<キー>" --visibility sensitive

# preview でも地図を確認したいなら同じものを preview にも入れる
eas env:create --environment preview \
  --name GOOGLE_MAPS_API_KEY --value "<キー>" --visibility sensitive
```

EAS CLI はバージョンでフラグが変わるため、通らなければ `eas env:create --help` を見ること。

**確認方法**: ビルド後の設定に鍵が入っているかは、ローカルでは次で見える。

```bash
npx expo config --type public --json | python3 -c \
  "import json,sys; print(json.load(sys.stdin)['plugins'])" | grep -o 'androidGoogleMapsApiKey'
```

## §4 ビルドと提出

```bash
# AAB を作る（eas.json の production は buildType: app-bundle）
eas build --platform android --profile production

# クローズドテスト（alpha）へアップロード ← 12 人 × 14 日の要件はこのトラックが対象
eas submit --platform android --profile closed-testing

# 製品版アクセスが下りたあとは production トラックへ
eas submit --platform android --profile production
```

`eas.json` の `submit` にトラック別のプロファイルを 2 つ置いてある。
**内部テスト（internal）は要件にカウントされない**ため、テスト期間中は
`closed-testing`（Play の API 上は `alpha`）を使うこと。

`eas submit` には **Google Play のサービスアカウント鍵（JSON）** が必要。Play Console と
Google Cloud で発行し、初回は `eas submit` の対話で登録する。

`versionCode` は `eas.json` の `cli.appVersionSource: "remote"` + `autoIncrement: true` で
EAS が管理する。手で指定しない。現在の値は次で確認できる。

```bash
eas build:version:get -p android
```

## §5 Play Console に入力する内容

> [!IMPORTANT]
> **iOS 側の申告（`apple/README.md`）と食い違わせないこと。** 同じアプリについて 2 つのストアで
> 違うことを言うと、どちらかが事実と違うことになる。下記は `apple/README.md` に記録された
> iOS の回答から導いたもの。iOS 側を変えたらここも直す。

### データセーフティ（位置情報は「収集する」と答える）

iOS の App Privacy では **「詳細な位置情報を収集 / 用途はアプリの機能 / ユーザの個人情報には
紐付けない / トラッキング目的では使用しない」**と申告済み。Play でもこれに合わせる。

| 項目                             | 回答                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------- |
| 位置情報を収集するか             | **はい**（正確な位置情報）                                                                     |
| 用途                             | **アプリの機能**（地図表示・近い避難所や観光スポットまでの距離計算）                           |
| ユーザー ID と紐付けるか         | **いいえ**                                                                                     |
| 第三者と共有するか               | **いいえ**。経路案内は利用者の操作で外部地図アプリへ座標を渡すが、これは利用者が起点の受け渡し |
| 必須か任意か                     | **任意**（許可しなくてもアプリは使える）                                                       |
| 通信の暗号化                     | **はい**（HTTPS）                                                                              |
| データ削除をリクエストできるか   | 自社サーバーに保存していないため該当しない                                                     |
| 個人情報（氏名・メール等）の収集 | **なし**（v1 はアカウント作成が無い）                                                          |

> 「端末内で使うだけなら収集ではない」という解釈もありうるが、**iOS で「収集する」と
> 申告している**ので、Play で「収集しない」と答えると食い違う。申告は揃える。

### コンテンツのレーティング（IARC）

iOS の年齢制限は **4+**。Play のレーティングも全年齢相当になるはず。

- ユーザー生成コンテンツ **なし**（`IS_USER_CONTENT_ENABLED = false`）
- 暴力・性的表現・ギャンブル・薬物・不適切な言葉 いずれも なし
- 広告 なし
- ユーザー間のやりとり・位置情報の共有機能 なし

### 対象ユーザーと内容（**レーティングとは別の質問**）

ここは「何歳向けに作ったか」を聞かれる。**レーティング 4+ と「子ども向け」は別物。**

- 対象年齢: **13 歳以上を選ぶ**（12 歳以下を含めると**ファミリー向けポリシー**の対象になり、
  広告・データ取り扱い・デザインの追加要件がかかる）
- 子ども向けの訴求はしない。iOS でも「子ども向け」は選択していない
- アプリは訪日観光客向けであり、未成年を主な対象にしていない

> アプリ内には「18 歳未満には個人情報を扱う機能を出さない」ゲートがある（#522）。これは
> サインインを解禁したとき（#556）に関係する。v1 ではサインイン自体が無いため、
> ストアの申告には影響しない。

### アプリのアクセス権

- **全機能が制限なく利用可能**（ログイン不要）。審査用のテストアカウントは不要
- iOS でも「サインインが必要です」のチェックは外している

### その他

- プライバシーポリシー URL: https://kobe-in-your-pocket.github.io/privacy/
- 広告: なし / アプリ内購入: なし
- カテゴリ: 旅行＆地域（iOS のプライマリカテゴリ「旅行」に合わせる）
- 著作権表記: `2026 KOBE in Your Pocket`

### ストアの掲載情報

| 項目                               | 上限        | 備考                                                                                                |
| ---------------------------------- | ----------- | --------------------------------------------------------------------------------------------------- |
| アプリ名                           | 30 文字     | `KOBE in Your Pocket`（iOS と同じ綴り。`Pocker` ではない）                                          |
| 簡単な説明                         | 80 文字     |                                                                                                     |
| 詳しい説明                         | 4,000 文字  |                                                                                                     |
| アプリアイコン                     | 512×512 PNG |                                                                                                     |
| フィーチャーグラフィック           | 1024×500    | **Play では必須。iOS には無い成果物**                                                               |
| スマートフォンのスクリーンショット | 2〜8 枚     | **アスペクト比 16:9〜9:16 の範囲内**。iOS 用の 1320×2868（約 1:2.17）は**範囲外なので流用できない** |

ロケールは iOS と同じく **英語（アメリカ）と日本語**を用意する。アプリ内は 4 言語
（ja / en / ko / zh）に対応しているので、余力があれば韓国語・中国語も追加できる。

## 付記: リポジトリ側で済んでいること

- `android.package` = `com.kobeinyourpocket.client`（iOS のバンドル ID と同じ）
- アダプティブアイコン（前景 / 背景 / モノクロ）を設定済み
- `eas.json` の `production` が `buildType: app-bundle`（Play は AAB 必須）
- `submit.production.android.track` = `internal`
- **不要な権限を外した**（`android.blockedPermissions`）。Expo の既定マニフェストは
  「OPTIONAL PERMISSIONS, REMOVE WHATEVER YOU DO NOT NEED」として
  `SYSTEM_ALERT_WINDOW` / `VIBRATE` / `READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE` を
  入れてくる。どれも使っておらず、Play の掲載ページには宣言した権限がそのまま並ぶため外した
  - 副作用: Android の dev client で開発メニューのフローティングバブルが出なくなる。
    端末を振る、または `adb shell input keyevent 82` で開ける
- `targetSdkVersion` は Expo SDK 56 が管理する。Play の target API レベル要件を満たさない場合は
  アップロード時にエラーで分かる
