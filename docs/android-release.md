# Android（Google Play）リリース手順

iOS 版と同じ `develop` のコードを Google Play に出すための手順。
**リードタイムの長いものから書いてある。順番どおりに進めること。**

## 前提: 1.1.0 で出す機能の範囲

1.1.0 から `src/shared/config/feature-flags.ts` の `IS_USER_CONTENT_ENABLED` が `true` になり、
**サインイン・アカウント作成・レビュー投稿・通報・ブロック・退会を提供する**。v1（1.0.x）は
これらを出していなかったため、Play 側でやることが増えている（#732）。

扱う情報の正は**プライバシーポリシー（版数 2026-10-16）**。
§5 の回答はこれと食い違わないようにする。

| 項目                        | 1.1.0 での扱い                                                                                                                                   |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| サインインの方法（Android） | **メールアドレス + パスワード / Google**。Apple でサインインは iOS だけ（`use-apple-sign-in.ts` が iOS 以外ではボタンを出さない）                |
| Google サインイン           | **使う**。Google Cloud に Android 用の OAuth クライアントを作り、§2 と同じ 3 つの SHA-1 を登録する必要がある（§2）                               |
| アカウント削除              | アプリ内（設定 → 退会）で削除できる。加えて Play は**アプリを入れ直さずに削除を要求できる Web の窓口**を求める（§5「データの削除」）             |
| ユーザー生成コンテンツ      | **ある**。レビューは表示名とともに他の利用者に公開される。通報・ブロックはアプリ内で行える                                                       |
| Google マップ               | **使う**。API キーと SHA-1 の登録が必要（§2）                                                                                                    |
| 位置情報                    | 使う。基本は端末内で完結する。**徒歩経路の案内を実行したときだけ**、出発地・目的地の座標が OpenRouteService へ送られる                           |
| 18 歳未満                   | 同意画面で 18 歳未満と答えた場合、位置情報・サインイン・レビュー投稿を出さない（#522）                                                           |
| 要求する権限                | `ACCESS_COARSE_LOCATION` / `ACCESS_FINE_LOCATION`。アイコン画像の選択（`expo-image-picker`）で権限が増えていないかは、§4 のとおり AAB で確認する |

## §1 Play デベロッパーアカウント

**最長のリードタイム。ここが全体の律速。**

|                  | 個人アカウント                                    | 組織アカウント                         |
| ---------------- | ------------------------------------------------- | -------------------------------------- |
| 製品版公開の前提 | **12 人以上 × 14 日連続のクローズドテストが必須** | 不要                                   |
| 登録に必要なもの | 本人確認書類                                      | **D-U-N-S 番号**（取得に時間がかかる） |

iOS を組織の Apple Developer で取得しているなら、Play も組織登録にすればクローズドテストの
要件が外れる。ただし D-U-N-S 取得の待ち時間とのトレードオフ。**どちらが早いかは
「12 人のテスターを 14 日間確保できるか」で決まる**ので、先に判断すること。

クローズドテストをやる場合、14 日間はテスターが**実際にインストールして使い続ける**必要がある
（入れただけで放置すると条件を満たさない扱いになる報告がある）。人数と期間は余裕を持たせる。

### クローズドテストの進め方

1. **クローズドテストのトラックにリリースする**。`eas submit` は内部テスト（`internal`）に
   上げるので、Play Console で内部テストのリリースをクローズドテストへ昇格させる。
   **内部テストは 14 日の条件に数えられない**
2. **テスターを登録する**。クローズドテスト → テスター → メーリングリストに、テスターの
   **Google アカウントのメールアドレス**を入れる。Google アカウントになっていないアドレス
   （学校のアドレスなど）は登録しても参加できない
3. **参加してもらう**。テスタータブの参加用 URL
   （`https://play.google.com/apps/testing/com.kobeinyourpocket.client`）を送り、登録した
   Google アカウントで開いて「テスターになる」→ Play ストアからインストール、まで
   してもらう。名簿に載っている・URL を開いただけでは数えられない
4. **14 日間続ける**。参加中のテスターが 12 人を下回らないようにする。期間中に何度か
   開いてもらうよう声をかける。期間中にアップデートを配ってよい
5. **テスターの意見と対応を記録しておく**。製品版の申請で「テストで何を確認したか」
   「どんな意見があり、どう直したか」を聞かれる。Issue に残しておくと答えやすい
6. **製品版へのアクセスを申請する**。14 日が経つと Play Console のダッシュボードから申請
   できる。審査は通常 7 日ほど。申請の前に §5 の回答を見直すこと

## §2 Google Cloud 側（マップの API キー）

マップの API キーを「Android アプリ」で制限している場合、**呼び出し元の署名証明書の SHA-1 を
すべて登録する**必要がある。登録するのは 3 つ。

| #   | 鍵                    | 使う場面                                        | 取り方                                        |
| --- | --------------------- | ----------------------------------------------- | --------------------------------------------- |
| 1   | デバッグキーストア    | ローカルの開発ビルド                            | 下記コマンド                                  |
| 2   | EAS のアップロード鍵  | `eas build` で作った APK / AAB を直接入れたとき | `eas credentials -p android`                  |
| 3   | **Play アプリ署名鍵** | **Play から配信されたアプリ**                   | Play Console → リリース → 設定 → アプリの署名 |

```bash
# 1. デバッグキーストア
keytool -list -v -keystore ~/.android/debug.keystore \
  -alias androiddebugkey -storepass android -keypass android

# 2. EAS のアップロード鍵（対話形式。Keystore の情報に SHA-1 が出る）
eas credentials -p android
```

> [!WARNING]
> **3 番目（Play アプリ署名鍵）を忘れると、切り分けづらい不具合になる。**
> Play はアップロードした AAB を自分の鍵で**再署名**して配信するため、EAS から直接入れた
> ビルドでは動くのに、**Play 経由で入れたものだけマップが表示されない**という形で出る。
> 3 番目の SHA-1 は最初の AAB をアップロードした後でなければ Play Console に出てこないので、
> 「アップロード → SHA-1 を登録 → 配信して確認」の順になる。

API キー自体は 1 つで、3 つの SHA-1 を同じキーの「アプリの制限」に並べて登録する。

### Google サインインの OAuth クライアント

Android の Google サインインは、アプリからは Web 用のクライアント ID
（`EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`）しか渡さない（`use-google-sign-in.ts`）。ただし
**同じ Google Cloud プロジェクトに、Android 用の OAuth クライアント（パッケージ名
`com.kobeinyourpocket.client` + SHA-1）が無いとサインインが失敗する**
（`DEVELOPER_ERROR`）。

SHA-1 はマップと同じく上の 3 つが必要。Android 用の OAuth クライアントは 1 つに
SHA-1 を 1 つしか登録できないので、**鍵ごとに 1 つずつ作る**。

> [!WARNING]
> マップと同じ罠がある。Play アプリ署名鍵の SHA-1 を登録し忘れると、EAS から直接入れた
> ビルドではサインインできるのに、**Play 経由で入れたものだけ Google サインインが失敗する**。

## §3 EAS の環境変数

`eas.json` の `build.production.env` には `EXPO_PUBLIC_API_BASE_URL` しか書いていない。
**マップの API キーは EAS の環境変数に入れる**（リポジトリに置かない）。

ローカルの `.env` はダミー値が入っていることがあるので、ローカルでマップが出ないことと
本番ビルドは別問題として切り分けること。

```bash
# 現在の登録内容を確認
eas env:list --environment production

# 登録（値を履歴に残したくないので、引数なしで対話形式にするのも可）
eas env:create --environment production \
  --name GOOGLE_MAPS_API_KEY --value "<キー>" --visibility sensitive

# preview でも地図を確認したいなら同じものを preview にも入れる
eas env:create --environment preview \
  --name GOOGLE_MAPS_API_KEY --value "<キー>" --visibility sensitive
```

EAS CLI はバージョンでフラグが変わるため、通らなければ `eas env:create --help` を見ること。

**確認方法**: ビルド後の設定に鍵が入っているかは、ローカルでは次で見える。

```bash
npx expo config --type public --json | python3 -c \
  "import json,sys; print(json.load(sys.stdin)['plugins'])" | grep -o 'androidGoogleMapsApiKey'
```

## §4 ビルドと提出

```bash
# AAB を作る（eas.json の production は buildType: app-bundle）
eas build --platform android --profile production

# Play へアップロード（submit.production.android.track = internal）
eas submit --platform android --profile production
```

`eas submit` には **Google Play の サービスアカウント鍵（JSON）** が必要。Play Console と
Google Cloud で発行し、初回は `eas submit` の対話で登録する。

`versionCode` は `eas.json` の `cli.appVersionSource: "remote"` + `autoIncrement: true` で
EAS が管理する。手で指定しない。現在の値は次で確認できる。

```bash
eas build:version:get -p android
```

初回アップロードは `internal`（内部テスト）に入る。そこから
内部テスト → クローズドテスト → 製品版 と上げていく。§1 のクローズドテスト要件は
**製品版に上げる前**に満たす必要がある。

**宣言している権限を AAB で確認する**: Play Console → リリース → App Bundle Explorer で、
アップロードした AAB の権限一覧を見られる。位置情報（`ACCESS_COARSE_LOCATION` /
`ACCESS_FINE_LOCATION`）以外が並んでいたら、`app.config.ts` の
`android.blockedPermissions`（付記）で外すか、使う理由を説明できるようにする。

## §5 Play Console に入力する内容

**プライバシーポリシー（https://kobe-in-your-pocket.github.io/privacy/ 、版数 2026-10-16）と
食い違わないようにする。** 機能を変えてポリシーを改定したら、ここも合わせて直す。
iOS 側の App Privacy の回答とも揃える（iOS には Apple でサインインの分が加わる）。

### データセーフティ

Play の「収集」は**端末の外へ送ること**を指す（自社サーバー以外への送信も含む）。
Supabase・AWS・OpenRouteService のような、当チームの代わりに処理するサービスへの送信は
「共有」に当たらない。

**全般の質問**

| 質問                                   | 回答                                                       |
| -------------------------------------- | ---------------------------------------------------------- |
| 必須のデータ型を収集・共有しているか   | **はい**                                                   |
| 送信するデータはすべて暗号化しているか | **はい**（通信はすべて HTTPS）                             |
| アカウントを作成できるか               | **はい**（ユーザー名とパスワード、および OAuth（Google）） |
| アカウント削除の Web の URL            | 下の「データの削除」を参照                                 |
| データの削除をリクエストできるか       | **はい**（アプリ内の退会、およびお問い合わせ窓口）         |

**収集するデータ**（どれも「共有」はしない。アカウント作成と経路案内は利用者が選ぶので、
すべて「任意」）

| データの種類                                            | 中身                                                                | 目的                                 |
| ------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------ |
| 個人情報 → 名前                                         | 表示名（Google から受け取る名前を含む）                             | アプリの機能、アカウント管理         |
| 個人情報 → メールアドレス                               | サインインに使うメールアドレス                                      | アプリの機能、アカウント管理         |
| 個人情報 → ユーザー ID                                  | アカウントの ID                                                     | アプリの機能、アカウント管理         |
| 写真と動画 → 写真                                       | プロフィールのアイコン画像                                          | アプリの機能                         |
| アプリのアクティビティ → その他のユーザー作成コンテンツ | レビューの本文・評価、通報の補足説明                                | アプリの機能                         |
| アプリのアクティビティ → その他の操作                   | 通報・ブロックの記録                                                | アプリの機能（不適切な投稿への対応） |
| 位置情報 → 正確な位置情報                               | 徒歩経路を出すときの出発地・目的地の座標（OpenRouteService へ送る） | アプリの機能                         |

収集しないもの:

- 位置情報の履歴（当チームのサーバーには送らない。地図と距離の表示は端末内で計算する）
- 広告 ID・端末 ID、行動トラッキング、第三者の解析ツール（入れていない）
- 端末内にだけ保存するもの（表示言語、同意の記録、避難所のキャッシュ）は「収集」に当たらない

> [!NOTE]
> 経路案内で OpenRouteService へ座標を直接送っているのは、クライアントに API キーを
> 持たせている今の作り（Client #686）のため。backend 経由に変えても座標が端末の外へ出る
> ことは変わらないので、この回答は変わらない。

### データの削除（アカウント削除の Web 窓口）

Play は、アカウントを作れるアプリに**アプリを入れ直さなくても削除を要求できる Web の窓口**を
求める。プライバシーポリシーの次の章が条件を満たすので、その URL を登録する。

- URL: https://kobe-in-your-pocket.github.io/privacy/
- 第 7 章: アプリ内（設定）での退会手順と、お問い合わせ窓口からの削除の請求
- 第 6 章: 消えるデータと、残るデータ（他の利用者が行った通報の記録）・保存期間

Play が求めているのは「アプリ名・開発者名が分かること」「削除の要求手順」「消えるデータと
残るデータ・期間」の 3 点。ポリシーを改定するときに、この 3 点を消さないこと。

### コンテンツのレーティング（IARC）

- ユーザー同士がコンテンツをやり取りできるか: **はい**（レビューが表示名とともに公開される）
- 利用者の現在地をほかの利用者に共有するか: **いいえ**
- デジタル商品の購入: **いいえ**
- 暴力・性的表現・ギャンブル・薬物の表現: なし
- 広告: なし

### ユーザー生成コンテンツ（Play のポリシー）

レビューの投稿があるため、Play の UGC ポリシーの対象になる。次がアプリにあることを確認済み。

- 投稿の前に利用規約に同意してもらう（初回起動の同意画面。規約に禁止事項がある）
- アプリ内で投稿を通報できる
- アプリ内でほかの利用者をブロックできる
- 運営が通報を確認し、投稿を非表示にできる（管理画面）

### 対象ユーザーと内容

- 対象年齢: **18 歳以上**。ファミリー向けポリシーの対象外になる
- 子ども向けの訴求はしない
- 18 歳未満と答えた人には個人情報を扱う機能を出さない（前提の表）が、これは対象年齢を
  広げるものではない

### アプリのアクセス権

- **一部の機能にサインインが必要**（レビューの投稿・編集・削除、アカウント編集、退会）
- 審査用のテストアカウント（メールアドレス + パスワード）を用意して登録する
  - 2 段階認証やメールの確認が要らない状態にしておく
  - 製品版の申請の前に、そのアカウントでサインインできることを確認する
- 手順の説明に次を書く（審査は英語環境なので、ボタン名は英語の表示に合わせる）
  1. 初回起動の同意画面で「I am 18 or older — accept and start」を押す
     （18 歳未満を選ぶとサインインの欄が出ない）
  2. 「Settings」タブ →「Log in / Sign up」→「Log in」で、メールアドレスとパスワードを入れる

### その他

- プライバシーポリシー URL: https://kobe-in-your-pocket.github.io/privacy/
- 広告: なし
- アプリ内購入: なし

## 付記: リポジトリ側で済んでいること

- `android.package` = `com.kobeinyourpocket.client`（iOS のバンドル ID と同じ）
- アダプティブアイコン（前景 / 背景 / モノクロ）を設定済み
- `eas.json` の `production` が `buildType: app-bundle`（Play は AAB 必須）
- `submit.production.android.track` = `internal`
- **不要な権限を外した**（`android.blockedPermissions`）。Expo の既定マニフェストは
  「OPTIONAL PERMISSIONS, REMOVE WHATEVER YOU DO NOT NEED」として
  `SYSTEM_ALERT_WINDOW` / `VIBRATE` / `READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE` を
  入れてくる。どれも使っておらず、Play の掲載ページには宣言した権限がそのまま並ぶため外した
  - 副作用: Android の dev client で開発メニューのフローティングバブルが出なくなる。
    端末を振る、または `adb shell input keyevent 82` で開ける
- `targetSdkVersion` は Expo SDK 56 が管理する。Play の target API レベル要件を満たさない場合は
  アップロード時にエラーで分かる
